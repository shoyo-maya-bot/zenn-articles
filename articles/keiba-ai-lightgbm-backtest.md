AIエージェントと一緒に、競馬の予想モデルを作りました。Pythonと、表形式のデータに強い機械学習ライブラリのLightGBMを使っています。

先に結論を書きます。**長く続けて確実に勝てる買い方は、見つかりませんでした。** それでも、機械学習で「予測して、確かめる」流れを学ぶ題材としては、とても良いものでした。

この記事では、予測モデルの作り方よりも、**予測が本当に当たっているかを確かめる方法**を中心に紹介します。

:::message alert
この記事は、機械学習の題材として競馬を扱うものです。利益を保証するものではありません。馬券の購入は20歳以上が対象で、余裕のあるお金の範囲で楽しんでください。
:::

## 全体の構成

ファイルは役割ごとに分けています。

| ファイル | 役割 |
| --- | --- |
| `make_sample_data.py` | 動作確認用の架空のデータを作る |
| `features.py` | 過去の成績から特徴量を作る |
| `train.py` | LightGBMで学習する |
| `backtest.py` | 過去のレースで、買っていたらどうなったかを計算する |
| `predict.py` | 次のレースを予測する |

最初は架空のデータで最後まで動くことを確かめ、それから実際のデータに切り替えました。いきなり本物のデータで始めると、うまくいかないときに、データとプログラムのどちらが悪いのか分かりにくいからです。

### データの集め方

実際のデータは、公開されているレース結果を使いました。

データを集める前に、サイトの利用規約と robots.txt を必ず確認してください。自動での取得を禁止しているサイトもあります。取得するときは、アクセスの間隔を空けて、サイトに負担をかけないようにします。集めたデータは、個人の学習の範囲で使います。

## 一番大事なのは「未来のデータを使わない」こと

機械学習の予測で最も多い失敗が、**リーク**です。予測する時点では知りえない情報を、うっかり学習に使ってしまうことです。

競馬なら、たとえば次のようなものです。

- 予測したいレースの結果を含めて、騎手の勝率を計算してしまう
- 同じ日の、後のレースの結果を使ってしまう

リークがあると、検証では驚くほど当たります。でも、実際に使うとまったく当たりません。

### 対策：日付でずらして集計する

過去の成績は、**その日より前のデータだけ**で集計します。同じ日のレースも使いません。

さらに、それを確かめるテストも書いておきます。考え方を示すための簡略版です。

```python
def test_future_data_does_not_change_past_features():
    """未来のデータを足しても、過去の特徴量が変わらないこと"""
    df = load_sample()
    cutoff = "2025-06-01"
    past_only = build_features(df[df.date < cutoff])
    with_future = build_features(df)
    a = past_only.set_index(["race_id", "horse_id"]).sort_index()
    b = with_future[with_future.date < cutoff].set_index(["race_id", "horse_id"]).sort_index()
    pd.testing.assert_frame_equal(a, b[a.columns])
```

こうした確認で、実際に騎手の成績の集計にリークが見つかりました。テストがなければ、気づかないまま「よく当たるモデル」だと思い込んでいたはずです。

## オッズとAIを混ぜる

単勝のオッズは、たくさんの人の予想が集まったものです。実は、オッズから逆算した確率は、それだけでかなり正確です。

そこで、AIの予測とオッズを混ぜて使います。

```python
def blend_with_market(df, p_ai, w):
    """AIの勝率とオッズから逆算した勝率を、対数で混ぜる（w = AIへの信頼度）"""
    inv = 1 / df["odds"]
    p_mkt = inv / inv.groupby(df["race_id"]).transform("sum")
    lp = w * np.log(p_ai.clip(1e-6)) + (1 - w) * np.log(p_mkt.clip(1e-6))
    p = np.exp(lp)
    return p / p.groupby(df["race_id"]).transform("sum")
```

`w` は、AIをどれくらい信じるかです。学習期間の最後の部分で、一番よく当たる `w` を選びます。

`w` が0になったら、「AIはオッズ以上の情報を持っていない」という意味です。その場合は、買うべきではありません。モデルの実力を、オッズという強い比較相手で測れるのがこの方法の良いところです。

### 買う候補を絞る

確率とオッズを掛けた「期待値」が高い馬を買う候補にします。ただし、オッズが1.5〜50倍の馬だけに絞っています。

大穴の馬は、勝つことがめったにないので、確率の推定が不安定です。期待値が高く見えても、推定のずれでそう見えているだけのことが多いからです。

## バックテストで確かめる

バックテストは、「過去のレースで、このルールで買っていたらどうなったか」を計算することです。

ここでもリークに注意します。各月の予測は、**その月より前のデータだけで学習したモデル**で行います。

### 券種別の結果

過去1年分、3,330レースで、15通りの買い方を確かめました。主なものを抜き出します（実際の払戻金で計算）。

| 買い方 | 的中率 | 当たったときの平均配当 | 回収率 |
| --- | --- | --- | --- |
| 複勝 ◎ | 65% | 130円 | 85.3% |
| 複勝 ○ | 54% | 164円 | 87.8% |
| ワイド ◎-○ | 34% | 249円 | 83.8% |
| 馬連 ◎-○ | 17% | 500円 | 85.4% |
| 三連複 ◎○▲ 1点 | 10% | 848円 | 83.0% |
| 三連単 ◎→○→▲ 1点 | 2.6% | 2,945円 | 76.9% |
| 三連単 上位4頭ボックス | 23% | 7,353円 | 71.6% |

どの買い方も、回収率は100%を下回りました。配当が高い券種ほど、成績が悪くなっています。

### 高配当の券種ほど負けやすい理由

理由は2つあります。

**控除率が高い。** 馬券の売上から、先に一定の割合が差し引かれます。JRAの場合、単勝・複勝は20%、馬連・ワイドは22.5%、三連複は25%、三連単は27.5%です。

**当てるのが難しい。** 三連単は、1着から3着までを順番どおりに当てる必要があります。予測が少しずれるだけで外れます。

### 「100%超え」に飛びつかない

絞り込んだ買い方では、回収率が100%を超えることもありました。たとえば、オッズが割安な単勝だけを買う方法は、1年で134.6%でした。

ただし、買ったのは277点だけです。この数だと、結果のぶれは±68%ほどあります。100%を超えたのは、たまたまの可能性が十分にあります。

バックテストの数字を見るときは、次のことに気をつけます。

- **購入数が少ないと、ぶれが大きい。** 数百点では、ほとんど何も言えません
- **確定オッズで計算している。** 実際に買うときは締切までにオッズが動くので、結果は悪くなりやすいです
- **月ごとの成績も見る。** 1年の合計が良くても、ある月だけ大当たりしていることがあります

## 毎週答え合わせをする

バックテストは、過去のデータでの確認です。本当の実力は、これから行われるレースで確かめるしかありません。

そこで、毎週の流れを自動化しています。

| タイミング | やること |
| --- | --- |
| 金曜の夜 | 週末のレースを予測して、予想のページを更新する |
| 開催日の夜 | 結果を取り込み、予想の的中と回収率を記録する |
| 火曜の夜 | 新しい結果を加えて、モデルを学習し直す |

予想は、記録を残してから結果を見ます。後から「実はこう予想していた」と書き換えられないようにするためです。

成績が積み上がってきたら、ルールを変えるかどうかを判断します。数週間の結果では、まだ判断しません。

## AIエージェントと作るときのコツ

このプロジェクトは、AIエージェントと一緒に作りました。役に立った頼み方をまとめます。

- **最初に架空のデータで最後まで動かしてもらう。** 本物のデータに切り替えるのは、その後にする
- **リークのテストを書いてもらう。** 「未来のデータを足しても過去の特徴量が変わらないこと」を確かめるテストです
- **比較相手を決めてもらう。** 「オッズだけで予測した場合」と比べないと、AIのモデルが良いのか分かりません
- **都合の悪い結果も報告してもらう。** 「勝てる方法は見つからなかった」も、大事な結果です

## よくある失敗

**リークに気づかない**
検証で当たりすぎるときは、まずリークを疑いましょう。テストで確かめておくと安心です。

**比較相手を置かない**
的中率が高くても、人気順に買うのと同じ成績なら意味がありません。オッズだけの予測と比べましょう。

**少ない購入数の回収率を信じる**
数百点の結果は、ぶれが大きすぎます。購入数と、月ごとの推移も一緒に見ましょう。

**確定オッズの結果を、そのまま期待する**
実際に買うときのオッズは、確定オッズと違います。バックテストより悪くなる前提で考えましょう。

## まとめ

競馬の予想モデルは、機械学習の「予測して、確かめる」流れを学ぶのにちょうどいい題材です。

- 未来のデータを使わない（リークのテストを書く）
- オッズという強い比較相手と比べる
- バックテストの数字は、購入数とぶれを見てから判断する
- 本当の実力は、毎週の答え合わせで確かめる

そして何より、「勝てる方法は見つからなかった」という結果を、そのまま受け止めることが大事です。自分に都合のいい数字を探し始めると、どこかでリークや偶然を見落とします。
