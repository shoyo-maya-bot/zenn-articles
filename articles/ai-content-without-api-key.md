AIを組み込んだツールを作ろうとすると、多くの解説で「まずAPIキーを取得しましょう」と書かれています。ツールの中からAIのAPIを呼び出す作り方です。

ただ、APIは使った分だけ料金がかかります。個人で作るツールだと、料金がいくらになるか読めないのは不安です。キーの管理にも気を使います。

この記事では、**APIキーを使わずに、AIの判断を組み込んだツール**を作る設計を紹介します。題材は、配信のアーカイブから切り抜き動画を作るツールです。

## 考え方：判断と作業を分ける

切り抜き動画を作る作業は、大きく2種類に分けられます。

| 種類 | 例 | 向いている担当 |
| --- | --- | --- |
| 判断 | どの場面を使うか、字幕の誤字をどう直すか、タイトルをどうするか | AI |
| 作業 | 文字起こし、音量の分析、動画の切り出し、字幕の焼き込み | プログラム |

APIを使う設計では、プログラムの中からAIを呼んで、判断もまとめてやらせます。

この記事の設計では、判断は**普段使っているチャットのAI**に任せます。プログラムは作業だけを担当します。両者は、ファイルを通してやり取りします。

```mermaid
flowchart LR
  A[ツール: 分析] -->|candidates.md / transcript.txt| B[チャットのAI: 判断]
  B -->|edit.json| C[ツール: 書き出し]
```

チャットのAIは、すでに払っているサブスクリプションの範囲で使えます。ツールの中にAPIの呼び出しは1つもありません。

## 全体の流れ

使う側から見ると、手順は3つです。

1. `run.bat <動画のURLかファイル>` を実行する（分析）
2. チャットのAIに「〇〇の切り抜きを編集して」と頼む（判断）
3. もう一度 `run.bat <配信名>` を実行する（書き出し）

### 1. 分析：AIが判断しやすい材料を作る

最初の実行では、プログラムが次の作業をします。

- 動画を取得する（yt-dlp）
- 文字起こしをする（faster-whisper）
- 音量の変化を調べる
- 切り抜きの候補を書き出す

取得するのは、自分の配信など、切り抜きの許可がある動画だけにします。コラボ相手が映る場合は、相手の了承も取っておきます。

候補のファイル（`candidates.md`）には、声が急に大きくなった場面に印を付けておきます。盛り上がった場面の目安になるからです。

分析が終わると、プログラムは止まって、次にやることを表示します。

```text
Claudeに『配信切り抜きの〇〇を編集して』と伝えてください
```

### 2. 判断：チャットのAIが編集の指示を書く

チャットのAIは、`candidates.md` と文字起こし（`transcript.txt`）を読んで、編集の指示ファイル（`edit.json`）を書きます。

AIが決めるのは、次のようなことです。

- どの場面を使うか（離れた複数の場面をつなぐこともできる）
- 字幕の誤字の修正
- タイトル
- 画面のどこに注目させるか

`edit.json` の形は、別のファイル（`EDIT_FORMAT.md`）に書いておきます。AIはこのファイルを読んで、決まった形で指示を書きます。

### 3. 書き出し：指示どおりに動画を作る

2回目の実行では、プログラムが `edit.json` を読んで動画を書き出します。動画の組み立てには、Reactで動画を作れるRemotionを使っています。

一部だけ作り直したいときのオプションも用意しています。

```bash
run.bat 配信名 --only 03 05   # 3本目と5本目だけ作り直す
run.bat 配信名 --analyze      # 分析だけやり直す
```

## 設計のポイント

### 受け渡しのファイルの形を決めておく

AIとプログラムの間は、ファイルでつながっています。ファイルの形がぶれると、書き出しで失敗します。

そこで、`edit.json` の形を文書（`EDIT_FORMAT.md`）にして、AIに必ず読ませます。プログラム側でも、読み込むときに形をチェックして、おかしければ分かりやすいエラーを出します。

これは、AIに使わせるCLIの記事で書いた「機械が読める出力」と同じ考え方です。今回は逆向きで、AIが書いたものをプログラムが読みます。

### プログラムは「次にやること」を表示して止まる

分析が終わったところで、プログラムは次にやることを表示して止まります。

使う人は、AIとプログラムのどちらの番かを迷わずに済みます。AIにとっても、「ここから自分の番」がはっきりします。

### 準備は自動にする

動画のツールは、必要なものが多くなりがちです。Pythonのライブラリ、ffmpeg、フォント、BGM、Node.js、Remotionなどです。

これらは、セットアップ用のスクリプト（`setup_env.py`）で自動で入れるようにしています。最初の準備でつまずくと、ツールを使ってもらえないからです。

### ライセンスを確かめる

動画に使う素材やライブラリは、ライセンスを確かめておきます。

- フォント：Google Fontsのうち、OFL（SIL Open Font License）のもの
- Remotion：個人と、3人以下の会社は無料で使える（それ以外は有料のライセンスが必要）

### ツールごとにフォルダを分ける

同じ仕組みで、別の種類の動画を作るツールも作れます。ただ、1つのフォルダにまとめると、設定や素材が混ざってしまいます。ツールごとにフォルダを分け、それぞれにセットアップと説明書を置いています。

## この設計が向いているとき・向いていないとき

| 向いている | 向いていない |
| --- | --- |
| 人がその場にいて、チャットで頼める | 夜中に無人で、大量に処理したい |
| 1回あたりの判断が多くない | 1日に何千件も判断が必要 |
| APIの料金やキーの管理を避けたい | 判断の結果をすぐに別のシステムに渡したい |

無人で大量に動かしたい場合は、APIを使う設計のほうが向いています。個人で、自分が使う分を作るなら、この設計で十分なことが多いです。

## よくある失敗

**受け渡しのファイルの形を決めない**
AIが毎回少しずつ違う形で書き、書き出しで失敗します。形を文書にして、AIに読ませましょう。

**プログラムが止まらずに先へ進む**
AIの判断を待たずに書き出しが始まると、古い指示で動画ができてしまいます。判断が必要なところで止めて、次にやることを表示しましょう。

**AIに作業までやらせる**
文字起こしや動画の切り出しは、プログラムのほうが速くて確実です。AIには判断だけを任せましょう。

**素材のライセンスを確かめない**
公開する動画では、フォントや音楽のライセンスが問題になります。最初に確かめておきましょう。

## まとめ

AIをツールに組み込むのに、必ずしもAPIキーは要りません。

- 判断はチャットのAI、作業はプログラムに分ける
- 両者はファイルでやり取りし、ファイルの形は文書にしておく
- プログラムは、AIの番が来たら止まって知らせる

AIを「ツールの部品」ではなく「一緒に作業する相手」として扱う設計です。料金を気にせず試せるので、最初の1本を作るにはちょうどいい形だと思います。
