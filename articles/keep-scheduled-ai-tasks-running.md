AIエージェントには、決まった時間に仕事をさせる「スケジュールタスク」を設定できます。毎朝のニュースまとめ、毎週のレポート、記事の投稿などです。

便利な反面、数が増えると困ったことが起きます。気づいたら止まっている。朝に失敗したのに、夜まで誰も気づかない。使用量の上限に当たって、まとめて失敗する。

この記事では、AIの定期タスクを止めずに回すための工夫を4つ紹介します。

1. 使用量の上限を知る
2. モデルを使い分ける
3. 実行時間を分散させる
4. 見張り役のタスクを置く

例はClaudeのスケジュールタスクですが、考え方は他のAIサービスでも同じです。

## 1. 使用量の上限を知る

AIのサブスクリプションには、一定時間あたりに使える量の上限があります。上限に当たると、その時間帯はAIが動けなくなります。

ここで大事なのは、**チャットとスケジュールタスクは同じ上限を分け合っている**ことです。朝にタスクがたくさん動くと、そのあと人がチャットで頼んだ仕事まで止まることがあります。

### どのタスクが重いかを調べる

まずは、どのタスクが使用量を多く使っているかを把握します。重くなりやすいのは、次のようなタスクです。

- 動画や画像を作る（ファイルが大きく、作業の手数も多い）
- 長い文章をいくつも書く
- たくさんのページを調べる

逆に、一覧を見て異常がないか確かめるだけのタスクは軽く済みます。

### 止める・減らすも立派な対策

重いタスクを全部残したまま工夫するより、思い切って減らすほうが効くこともあります。

- 最近ほとんど成果を使っていないタスクを止める
- 1時間ごとに動いていたものを、1日3回にする
- 毎日のものを、平日だけや週1回にする

「本当に毎回必要か」を見直すだけで、上限に当たる回数はかなり減ります。

## 2. モデルを使い分ける

すべてのタスクを一番性能の高いモデルで動かす必要はありません。

| タスクの性質 | 向いているモデル | 例 |
| --- | --- | --- |
| 判断が難しい、文章の質が大事 | 高性能なモデル（Opusなど） | 技術記事の執筆、調査レポート |
| 決まった手順を確実にこなす | 軽めのモデル（Sonnetなど） | 一覧のチェック、在庫の確認、定時の投稿 |

決まった手順をこなすだけのタスクは、軽めのモデルでも十分に動きます。軽いモデルは使用量の消費も少なめなので、上限に余裕が生まれます。

迷ったら、まず軽いモデルで数回動かしてみて、結果の質に問題がないかを確かめましょう。

## 3. 実行時間を分散させる

タスクを作るとき、つい「朝7時」「朝8時」のように、きりのいい時間に集めてしまいがちです。

すると、朝の同じ時間帯にタスクが集中して、同じ上限を取り合います。後から動いたタスクほど、上限に当たって失敗しやすくなります。

対策は簡単で、時間をばらします。

- 重いタスク同士は、数時間あける
- 朝・昼・夜に振り分ける
- 「7:00」ではなく「7:05」のように、きりのいい時刻を少しずらす

最後の項目は、サービス側の混雑を避けるためです。多くの人が0分ちょうどにタスクを設定するので、少しずらすだけで遅れにくくなります。

## 4. 見張り役のタスクを置く

工夫をしても、失敗をゼロにはできません。そこで、**他のタスクを見張るタスク**を1つ置きます。

### 見張り役が確かめること

見張り役は、タスクの一覧と、それぞれの最後の実行結果を見ます。調べるのは次の4つです。

| 状態 | 判定のしかた |
| --- | --- |
| 失敗 | 最後の実行が成功で終わっていない |
| 止まっている | 実行が始まってから3時間たっても終わっていない |
| 実行されていない | 予定の時刻を2時間過ぎても、実行の記録がない |
| 短すぎる | 動画を作るタスクが1分未満で終わったなど、中身がなさそう |

4つ目は見落としがちです。「成功」と記録されていても、実際には何もしていないことがあります。

### 見張る時間

見張り役は、1日に数回動かします。最初は夜に1回だけにしていましたが、それだと朝の失敗に夜まで気づけません。朝・昼・夜の3回に増やしました。

見張り役自体は軽い作業なので、軽めのモデルで十分です。

### 失敗したときの動き方

見張り役には、失敗を見つけたときの動き方も決めておきます。

```markdown
## 失敗を見つけたとき

- 一時的な失敗なら、1回だけ再実行する
  - 同じタスクの再実行は1日1回まで。2日続けては再実行しない
  - 再実行してから3時間は、「止まっている」と判定しない
- 使用量の上限で失敗していた場合
  - 見張り役が動けている時点で、上限は回復している
  - 1回の見張りで再実行するのは2件まで（大事なものから）
  - 次の予定まで6時間以上あるときだけ再実行する
- PCとの接続が必要なタスクで、PCがつながっていない場合
  - 再実行しない。利用者にアプリを開くよう伝える
- タスクの指示文は、見張り役が書き換えない
```

ポイントは、**再実行に上限を付けること**です。上限がないと、失敗し続けるタスクを何度も再実行して、使用量をさらに減らしてしまいます。

また、見張り役がタスクの中身を勝手に直さないようにしています。直すべきかどうかは、人が判断します。

### 報告は短く

見張り役の結果は、表にして記録しておきます。人への報告は、**新しく問題が起きたときだけ、5行以内**にします。

毎回「異常なし」と報告されると、人は報告を読まなくなります。本当に問題が起きたときに見逃さないよう、知らせるのは必要なときだけにします。

## チャットは自動では再開しない

1つ注意があります。スケジュールタスクは、次の予定時刻になれば自動で動きます。一方、人がチャットで頼んだ仕事が上限で止まった場合は、自動では再開しません。

上限が回復したあとに「続けて」と送れば、続きから再開できます。

## よくある失敗

**全部のタスクを朝に集める**
同じ時間帯に上限を取り合い、後のタスクほど失敗します。重いタスクは時間をあけて分散させましょう。

**全部のタスクを一番高性能なモデルで動かす**
決まった手順のタスクは、軽めのモデルで十分なことが多いです。

**見張り役を1日1回しか動かさない**
朝の失敗に夜まで気づけません。1日に数回動かしましょう。

**再実行に上限を付けない**
失敗し続けるタスクを何度も再実行して、使用量を食いつぶします。回数と条件を決めておきましょう。

**毎回「異常なし」と報告させる**
報告が多いと、本当の異常を見逃します。知らせるのは新しい問題だけにしましょう。

## まとめ

AIの定期タスクは、作ることよりも、止めずに回し続けることのほうが難しい仕事です。

- 重いタスクを把握して、減らせるものは減らす
- 決まった手順のタスクは、軽めのモデルで動かす
- 実行時間を分散させる
- 見張り役を置き、再実行には上限を付ける

これは、人のチームの運用とよく似ています。仕事を割り振るだけでなく、無理のない量にして、誰かが様子を見る。AIに任せる仕事が増えるほど、こうした運用の工夫が効いてきます。
