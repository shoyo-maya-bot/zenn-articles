AIにゲームを作らせようとすると、最初にぶつかる壁があります。AIはC#のコードは書けますが、Unityのエディタは触れません。

シーンにオブジェクトを置く、コンポーネントを付ける、Playして動きを見る。こうした作業は、人がマウスで操作するしかありませんでした。AIはファイルを書き換えるだけで、コンパイルエラーが出ても自分では気づけません。

この記事では、Unity MCPを使って、AIエージェントにUnityエディタを直接操作させる方法を紹介します。AIがエディタの中で作業し、エラーを読んで自分で直すところまで回せるようになります。

:::message
Unity MCPは更新が速いツールです。この記事は2026年10月時点の情報で書いています。メニュー名や設定項目は変わることがあるので、作業するときは配布ページも確認してください。
:::

## MCPとは

MCP（Model Context Protocol）は、AIに外部の道具をつなぐための共通の決まりごとです。

ハーネスの記事で、Toolsを「PCと社内システムのアカウント」にたとえました。MCPは、そのアカウントを発行する窓口のようなものです。Unity MCPを入れると、AIは「Unityを操作する」という道具を持てるようになります。

## できるようになること

Unity MCPを入れる前と後で、AIの作業はこう変わります。

| | 入れる前 | 入れた後 |
| --- | --- | --- |
| コードの変更 | ファイルを外から書き換える | エディタの中で書き換える |
| シーンの編集 | 人がマウスで操作する | AIがオブジェクトの作成・配置・コンポーネントの追加をする |
| エラーの確認 | 人がコンソールを見て、AIに貼り付ける | AIがコンソールのログを自分で読む |
| 動作の確認 | 人がPlayして、結果を伝える | AIがPlayモードで確かめ、スクリーンショットを撮る |

一番大きいのは、**エラーを自分で読んで直すループが回る**ことです。人がエラーをコピーして貼り付ける手間がなくなります。

## 使うもの

この記事では、次の組み合わせで説明します。

- Unity 2022.3（LTS）
- Unity MCP（パッケージ名 `com.ivanmurzak.unity.mcp`。この記事ではバージョン1.2.0を使用）
- AIエージェント：Claude Desktop

Unity MCPはOpenUPMで配布されています。OpenUPMは、Unity向けのオープンソースのパッケージを集めた配布サイトです。

## 入れ方

### 1. manifest.jsonをバックアップする

パッケージは、プロジェクトの `Packages/manifest.json` に追記して入れます。書き換える前に、必ずコピーを取っておきます。

```text
Packages/manifest.json → Packages/manifest.json.bak-mcp
```

うまくいかなかったときは、このファイルを戻せば元の状態に戻ります。

### 2. OpenUPMの登録先とパッケージを追記する

`manifest.json` に、2か所を追記します。

```json
{
  "scopedRegistries": [
    {
      "name": "package.openupm.com",
      "url": "https://package.openupm.com",
      "scopes": ["com.ivanmurzak", "extensions.unity"]
    }
  ],
  "dependencies": {
    "com.ivanmurzak.unity.mcp": "1.2.0"
  }
}
```

`dependencies` は、すでにある項目の中に1行足します。中身をまるごと置き換えないよう注意してください。

`scopedRegistries` は「このパッケージはOpenUPMから取ってくる」という指定です。`scopes` には、Unity MCPと、Unity MCPが使う別のパッケージの名前の先頭を書きます。

### 3. Unityを開いて、パッケージが入るのを待つ

Unityを開く（開いていればフォーカスを戻す）と、パッケージの読み込みが始まります。終わると、メニューに **Window > AI Game Developer** が増えます。

### 4. AIエージェントとの接続を設定する

**Window > AI Game Developer** を開いて、接続の設定をします。

| 項目 | 設定 |
| --- | --- |
| Connection | Custom |
| Transport | stdio |
| AI agent | Claude Desktop |

ここで設定すると、Claude Desktopの設定ファイルに、Unity MCPの起動方法が書き込まれます。自分で設定ファイルを編集する必要はありません。

### 5. Claude Desktopを完全に再起動する

ここが一番つまずきやすいところです。Claude Desktopは、起動したときにだけMCPの設定を読み込みます。

ウィンドウを閉じるだけでは、アプリが裏で動き続けていることがあります。タスクトレイ（メニューバー）からも終了して、完全に落としてから起動し直してください。

再起動しないままだと、設定ファイルには書き込まれているのに、AIからはUnityの道具が1つも見えない状態になります。

### 6. つながったか確かめる

Claude Desktopで、簡単な依頼をして確かめます。

```text
Unityの今開いているシーンにあるオブジェクトを一覧にしてください。
```

シーンの中身が返ってくれば、接続できています。

## 道具を増やす

入れた直後は、用意されている道具の一部だけが有効になっています。この記事の環境では、18個のうち7個が有効でした。

足りない操作があるときは、**Window > AI Game Developer** の画面で、使いたい道具を有効にします。最初は少なめで始めて、必要になったら増やすのがおすすめです。道具が多いほど、AIはどれを使うか迷いやすくなります。

## AIに渡す作業手順

道具をつないだだけでは、AIの作業はまだ安定しません。「どの順で作業し、何をもって完成とするか」を決めて、AIに渡しておきます。

手順の例です。

```markdown
## Unityで作業するときの手順

1. 作業の前に、コンソールのログを読み、今あるエラーを確認する
2. 変更は小さく分けて行う（スクリプト1つ、またはオブジェクト1つずつ）
3. 変更のたびにコンソールを読む。エラーが0件になるまで直す
4. Playモードに入り、意図どおりに動くかを確かめる
5. スクリーンショットを撮り、見た目を確認する
6. 報告には、直したエラーと、Playで確かめた内容を書く
```

ポイントは「エラーが0件になるまで」と「Playで確かめる」です。コンパイルが通っただけでは、動くかどうかは分かりません。

この手順を毎回プロンプトに書くのは大変なので、スキルとして保存しておくと便利です。スキルにしておけば、Unityの作業を頼んだときにAIが自分で読み込みます。

## Blenderも同じ考え方でつなげる

3Dモデルを作るBlenderにも、MCPがあります（blender-mcp）。Blender本体、Pythonのパッケージ管理ツールのuv、blender-mcpを入れれば、AIからBlenderを操作できます。

インストールはPowerShellのスクリプト1本にまとめられます。ただし、AIはユーザーのターミナルに直接入力できない環境もあります。その場合は、AIがスクリプトを用意し、人が1行だけ実行する、という分担にします。

## よくある失敗

**Claude Desktopを再起動していない**
設定は書き込まれているのに、道具が見えない状態になります。タスクトレイからも終了して、完全に再起動しましょう。

**manifest.jsonの中身をまるごと置き換える**
既存のパッケージの指定が消えて、プロジェクトが壊れます。追記するだけにして、事前にバックアップを取りましょう。

**同じプロジェクトを2つのエディタで開く**
stdioでの接続は、1つのプロジェクトにつき同時に1つまでです。同じプロジェクトを複数のエディタで開くと、接続がうまくいきません。

**コンパイルが通ったら完成にしてしまう**
エラーがなくても、動きが意図どおりとは限りません。Playモードでの確認とスクリーンショットを、手順に入れておきましょう。

**最初から道具を全部有効にする**
AIが使う道具を選びにくくなります。必要なものから少しずつ増やしましょう。

## まとめ

Unity MCPを入れると、AIは「コードを書くだけ」から「エディタの中で作って確かめる」ところまで進めます。

- OpenUPMの登録先とパッケージを `manifest.json` に追記する（先にバックアップ）
- **Window > AI Game Developer** で、stdio・Claude Desktopを選ぶ
- Claude Desktopを完全に再起動する
- 「エラー0件まで直す」「Playで確かめる」を手順として渡す

AIに道具を渡したら、その道具の使い方（手順）も一緒に渡す。ここまでやって、AIはゲーム作りの相棒になってくれます。
