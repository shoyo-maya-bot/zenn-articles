謎解きミステリーのサイト「[零課事件簿](https://shoyo-maya-bot.github.io/reika-jikenbo/)」を公開しました。毎日1問の小さな謎と、何章かで真相にたどり着く「事件ファイル」が遊べるサイトです。

このサイトは、**HTMLファイル1つだけ**で動いています。サーバーもデータベースも、ビルドの手順もありません。GitHubにファイルを置き、GitHub Pagesで公開しているだけです。ソースは [shoyo-maya-bot/reika-jikenbo](https://github.com/shoyo-maya-bot/reika-jikenbo) で見られます。

この記事では、この形でも「毎日問題が変わる」「進み具合が残る」「シリーズを追加していける」サイトをどう作っているかを紹介します。謎の答えのネタバレはしないので、遊ぶ前の方も安心して読んでください。

## どんなサイトか

| 機能 | 内容 |
| --- | --- |
| 本日の小謎 | 毎日0時（日本時間）に問題が変わる。連続正解の日数と、直近7日の記録が出る |
| 事件ファイル | 4つの章と最終章で1つの事件。資料を読み、問いに答えて進む。ヒントは段階的に出せる |
| 捜査官手帳 | 解いた数に応じてポイントがたまり、「巡査」から始まる階級が上がる |
| 次回予告 | 次の事件ファイルの公開までのカウントダウン |
| 結果のシェア | 解決後に、所要時間とヒントの回数をコピーできる（答えは含まない） |

これを、`index.html` の中のHTML・CSS・JavaScriptだけで作っています。

## 構成：ファイルは3つだけ

リポジトリにあるのは、この3つです。

```text
reika-jikenbo/
  index.html   ← サイトのすべて（約600行）
  README.md
  .nojekyll    ← GitHub Pages で Jekyll の処理を止める空ファイル
```

GitHub Pagesは、何もしなければJekyllという仕組みでファイルを加工してから公開します。`.nojekyll` を置くと、その処理を飛ばして、ファイルをそのまま公開します。1ファイルのサイトなら、これで十分です。

公開の手順は、リポジトリの Settings の Pages で、公開するブランチを選ぶだけです。pushすれば、少し待つとサイトに反映されます。

## 仕組み1：問題は「データ」として分けておく

このサイトで一番大事にしているのは、**画面を作るコードと、謎の中身（データ）を分けている**ことです。

事件ファイル、毎日の小謎、次回予告は、それぞれJavaScriptの配列やオブジェクトとして書いています。

```js
const FILES = [FILE01, FILE02];
const NEXT = { no:"FILE 03", title:"幽霊ホテルの時刻表", genre:"列車とアリバイ", date:"2026-10-18T19:00:00+09:00" };
const DAILY = [
  { q:"問題文", a:["こたえ", "答え"], ex:"解説" },  // 説明用のダミー
  // ...
];
```

1つの章は、こんな形をしています（中身は説明用のダミーです）。

```js
{ id:"c1", no:"第一章", title:"章のタイトル", lv:"難易度 ★☆☆",
  story:["物語の文章1", "物語の文章2"],
  doc:`<span class="tag">資料 1</span><h3>資料の見出し</h3>...`,
  q:"問いの文章",
  answers:["こたえ", "答え"],
  hints:["1つ目のヒント", "2つ目のヒント"],
  reveal:{ head:"答え：…", body:"解説の文章" } }
```

画面を作る関数は、このデータを読んで、どの事件でも同じ形で表示します。新しい事件を足すときは、データを1つ書いて `FILES` に加えるだけです。READMEにも、次のように書いています。

> 事件ファイルは `FILES` 配列、本日の小謎は `DAILY` 配列、次回予告は `NEXT` を編集して追加します。

### AIに追加を頼みやすくなる

データの形が決まっていると、AIに新しい問題の追加を頼むときにも便利です。形が決まっているので、AIが勝手に画面のコードを書き換える心配が減ります。

たとえば、エージェント型のAIに頼むならこう書きます。

> index.html の DAILY 配列に、小謎を5問追加してください。既存の問題と同じ形式（q、a、ex）に合わせ、a には表記ゆれの答えも入れてください。画面を作るコードは変更しないでください。

「どこに」「どの形式で」「何を変えないか」を書くのがコツです。これは、シリーズの別の記事で書いた「エージェントへの指示は、範囲と完了の条件とやってほしくないことを書く」と同じ考え方です。

## 仕組み2：サーバーなしで「毎日問題を変える」

毎日問題が変わるサイトというと、サーバーで日付を見て問題を選ぶ仕組みが必要に思えます。このサイトでは、訪問者のブラウザで計算しています。

```js
function jstDay(t = Date.now()){ return Math.floor((t + 9*3600e3) / 86400e3); }

const today = jstDay(), d = DAILY[today % DAILY.length];
```

1. 今の時刻（ミリ秒）に9時間を足して、日本時間にする
2. 1日のミリ秒で割って、「1970年1月1日から何日目か」という通し番号にする
3. その番号を問題の数で割った余りで、今日の問題を選ぶ

通し番号は日本時間の0時に1つ増えるので、問題も0時に変わります。誰がどの国から見ても、同じ日には同じ問題が出ます。

問題を使い切ると最初の問題に戻りますが、`DAILY` に問題を足していけば、回ってくるまでの日数が延びます。

連続正解の日数も、この通し番号で数えています。正解した日の番号を記録しておき、今日（まだ解いていなければ昨日）からさかのぼって、続いている日数を数えます。

## 仕組み3：答えの「表記ゆれ」を吸収する

謎解きで地味に大事なのが、答えの判定です。「正しいのに、書き方が違うだけで不正解」は、遊ぶ人をがっかりさせます。

このサイトでは、入力された答えと正解の両方を、同じルールで整えてから比べています。

```js
function norm(s){
  return String(s).normalize("NFKC").toLowerCase()
    .replace(/[ァ-ヶ]/g, c => String.fromCharCode(c.charCodeAt(0) - 0x60))
    .replace(/[\s　、。・,.!！?？「」『』"'（）()]/g, "")
    .replace(/さん$/, "");
}
```

やっていることは次のとおりです。

1. `normalize("NFKC")` で、全角の英数字を半角にそろえる
2. 英字を小文字にする
3. カタカナをひらがなにする（文字コードを一定の数だけずらす）
4. 空白や句読点、かっこを取り除く
5. 人名の答えのために、最後の「さん」を取り除く

さらに、正解は配列で複数持てるようにしています。ひらがな、漢字、別の書き方を並べておけば、どれで答えても正解になります。

時刻のように書き方が多い答えは、文字列を並べる代わりに、判定する関数を持たせています。

```js
// 説明用の例（実際の問題の答えではありません）：「午後3時15分」を正解にする場合
check: s => /^(午後|pm)?(3|03|15)(:|時)?15(分)?$/.test(s)
```

「午後3時15分」「15:15」「3時15分」のような書き方を、正規表現で1つの判定にまとめています。

## 仕組み4：進み具合はブラウザに保存する

解いた章、使ったヒントの数、毎日の小謎の記録は、ブラウザの `localStorage` に保存しています。

```js
const KEY = "reika-v2";
let st = { files:{}, daily:{} };
try { const s = JSON.parse(localStorage.getItem(KEY)); if (s) st = Object.assign(st, s); } catch(e){}
try { const old = JSON.parse(localStorage.getItem("reika-file01")); if (old && !st.files.file01) st.files.file01 = old; } catch(e){}
const save = () => { try { localStorage.setItem(KEY, JSON.stringify(st)); } catch(e){} };
```

工夫しているところは3つあります。

- **読み書きを必ず `try` で囲む。** プライベートブラウズなどでは、`localStorage` が使えないことがあります。そのときも、保存されないだけでサイトは動きます。
- **保存のキーにバージョンを付ける。** 保存する形を変えたときに、キーの名前（`reika-v2`）を変えれば、古い形のデータと混ざりません。
- **古いデータを引き継ぐ。** 事件ファイルが1つだけだった頃のキー（`reika-file01`）が残っていれば、新しい形に移します。前から遊んでいた人の記録が消えません。

サーバーに何も送らないので、訪問者の個人情報を預からずに済みます。そのかわり、記録はそのブラウザだけに残り、別の端末には引き継がれません。

## 仕組み5：また来たくなる仕掛け

1ファイルのサイトでも、遊ぶ人が戻ってきたくなる仕掛けは作れます。

- **連続正解と、直近7日の記録。** 毎日来る理由になります。
- **階級。** 章を解くと3点、事件を解決すると10点、小謎の正解で2点。ヒントを使うと少し減ります。「次の階級まであと何点」が出るので、少しずつ進めたくなります。
- **次回予告のカウントダウン。** 次の事件ファイルの公開日を、`NEXT` に日時で書いておくだけで表示されます。
- **答えを含まないシェア文。** 解決すると、所要時間とヒントの回数をまとめた文章をコピーできます。ネタバレせずに、遊んだことを広められます。

## 見た目と使いやすさの工夫

- **ダークモードに対応。** 色はCSSの変数にまとめ、OSの設定に合わせて切り替えています。
- **挿絵はSVGで描く。** 時計やろうそくなど、謎に使う図はJavaScriptでSVGを組み立てています。画像ファイルが要らず、ダークモードでも色が変わります。
- **読み上げに配慮。** 図には `aria-label` で説明を付け、正解・不正解のメッセージは `aria-live` で読み上げられるようにしています。
- **動きを減らす設定を尊重。** OSで「動きを減らす」設定をしている人には、アニメーションを止めています。

## この作りの弱点

もちろん、1ファイルの静的サイトには限界もあります。

**答えがソースから見える**
答えの判定はブラウザで行っているので、ページのソースを開けば答えが読めてしまいます。気軽に遊ぶサイトなら許容できますが、ランキングや賞品を付けるなら、答えをハッシュ値にする、判定をサーバーに移す、といった対策が必要です。

**記録が端末をまたがない**
`localStorage` はブラウザごとの保存なので、スマホとPCで記録は別々になります。

**ファイルが大きくなっていく**
事件ファイルを足すほど、`index.html` は長くなります。本数が増えてきたら、事件ごとのデータを別のJSONファイルに分けるのが次の一手です。

## 自分で作るときの手順

1. GitHubで新しいリポジトリを作り、`index.html` と空の `.nojekyll` を置く
2. Settings → Pages で、公開するブランチを選ぶ
3. まず、問題のデータの形を決める（問い、答えの配列、ヒント、解説）
4. データを読んで画面を作る関数を書く
5. 答えの判定に、表記ゆれを吸収する関数を入れる
6. 進み具合を `localStorage` に保存する（読み書きは `try` で囲む）
7. pushして、公開されたページをスマホでも確かめる

3番目を先にやるのがポイントです。データの形さえ決まれば、問題の追加は、自分でもAIに頼んでも簡単になります。

## よくある失敗

**表示のコードの中に問題を直接書く**
問題ごとにHTMLを書いていくと、問題を足すたびに表示のコードを触ることになり、壊しやすくなります。問題はデータとして分けましょう。

**答えの判定を厳しくしすぎる**
全角と半角、カタカナとひらがなの違いで不正解にすると、遊ぶ人が離れていきます。比べる前に、両方を同じルールで整えましょう。

**`localStorage` が必ず使える前提で書く**
使えない環境では、例外でスクリプトが止まり、サイトが真っ白になることがあります。読み書きは `try` で囲みます。

**保存の形を変えたのに、キーをそのままにする**
古い形のデータを新しいコードが読んで、表示が崩れることがあります。形を変えたらキーのバージョンを上げ、必要なら古いデータを移しましょう。

## まとめ

サーバーもビルドもなくても、工夫次第で「毎日遊べる」サイトは作れます。

- 問題はデータとして分け、追加はデータを書くだけにする
- 日付の計算はブラウザで行い、サーバーなしで日替わりにする
- 答えの表記ゆれは、比べる前に整えて吸収する
- 進み具合はブラウザに保存し、個人情報は預からない

[零課事件簿](https://shoyo-maya-bot.github.io/reika-jikenbo/)では、これからも事件ファイルを追加していく予定です。次の「FILE 03」は、10月18日の19時に公開予定です。よければ挑戦してみてください、捜査官。
