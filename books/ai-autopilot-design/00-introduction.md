AIエージェントに仕事を任せると、最初は感動します。
コードを書き、テストを回し、PRまで作ってくれます。
ところが毎日回すようになると、別の悩みが出てきます。

## よくある「任せたつもり」の状態

次のどれかに心当たりはないでしょうか。

- 夜に回したタスクが、朝見ると何もしていないのに「成功」になっている
- 同じ投稿が2回されていた
- 止めたはずの操作を、AIが別の方法でやっていた
- 気づいたら使用量の上限に当たって、翌日まで何も動かなかった
- 結局、毎回ログを開いて確認している

これは「任せた」ではなく「見張っている」状態です。
人の手間は減っていません。
むしろ、確認する場所が増えて疲れます。

## この本が目指すもの

この本のゴールは、次の状態です。

> 人が見るのは「結果」と「本当に判断が必要なこと」だけ。
> エラーは仕組みが拾い、直せるものは直し、直せないものは理由つきで止まる。

そのために必要なのは、賢いプロンプトではありません。
必要なのは、AIの外側に置く「仕組み」です。
この本では、その仕組みを7つの観点に分けて説明します。

| 章 | 扱うこと |
| --- | --- |
| 1章 | AIに任せてよい仕事と、人が持つべき仕事の線引き |
| 2章 | 「お願い」ではなく「強制」で守る |
| 3章 | 「できました」を信じない成功判定 |
| 4章 | 外部に書き込む前の5つの確認 |
| 5章 | 止まっても再開できる作り |
| 6章 | プラットフォームの上限とアカウントを守る |
| 7章 | コストの見積もりと課金の落とし穴 |
| 8章 | ゲーム制作にAIを使うときの型 |
| 9章 | チェックリスト集 |

## 想定している読者

- Claude Code や GitHub Copilot をすでに使っている人
- 定期タスクや GitHub Actions で、AIに毎日何かをさせたい人
- 個人開発で、記事・動画・ゲームなどを AI と作っている人

コマンドの細かい使い方は扱いません。
それは公式ドキュメントのほうが正確で新しいからです。
この本は「どう組み立てるか」「どこでつまずくか」に絞ります。
