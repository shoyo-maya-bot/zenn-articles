---
title: "7章 コストの見積もりと課金の落とし穴"
---

無人タスクは、人が見ていない間に使用量を消費します。
気づいたときには、月の枠を使い切っていた、ということが起こります。
この章では、コストを先に見積もる方法と、課金の仕組みでつまずきやすい点を扱います。

## 先に1回分を測る

いきなり毎日回す前に、1回分の消費を実際に測ります。

1. 対象を1件だけにして実行する（1ファイル、1記事、1動画）
2. 結果のJSONに含まれる使用量・費用の値を記録する
3. 「1回分 × 1日の回数 × 30日」で月の見込みを出す
4. 見込みが枠に収まるかを確かめてから、頻度を上げる

ある本の試算では、20ファイルのレビューを毎晩上位モデルで回すと、それだけで個人向けプランの枠に近い額になるとされていました。
軽いモデルへの振り分けやキャッシュの活用で、大きく下げられるとも書かれていました。

### サブエージェントの分も数える

使用量の表示が、サブエージェントの消費を含まない場合があります。
合計の費用を示す値（`total_cost_usd` のような項目）で見るようにします。

## 上限は3つの軸でかける

暴走したときの被害を限るため、上限は3つ全部にかけます。

| 軸 | 例 |
| --- | --- |
| 時間 | CI の `timeout-minutes` を30〜60分に（GitHub Actions の初期値は6時間） |
| 回数 | AIの最大ターン数 |
| 金額 | 1回あたりの予算の上限 |

目安は、正常時の実測の2〜3倍です。
上限に当たったら、それ自体を「異常のサイン」として人に知らせます。

さらに、変更量にも上限を付けると安心です。
「10ファイル・300行を超える変更は、中身を見ずに破棄する」といったルールです。

## 課金の仕組みは、使い方で変わる

ここは特に変化が速い部分です。
必ず公式の料金ページを確かめてください。

考え方として押さえておきたいのは、次の2点です。

1. **対話で使うときと、プログラムから使うときで、消費する枠が違うことがある**
   ある本によると、CLIの非対話モードや CI、SDK からの利用は、対話とは別の枠から消費される仕組みになったとされています。
   定期タスクを増やす前に、自分のプランでどう数えられるかを確かめます。

2. **APIキーを渡すと従量課金になる**
   GitHub Actions の例などで、APIキーを環境変数に設定する書き方をよく見かけます。
   APIキーを使うと、プランの枠ではなく従量課金になります。
   従量課金を避けたいなら、プラン用の認証方式が使えるかを公式で確かめます。
   枠を超えたときに従量課金で動き続ける設定がある場合は、それが有効になっていないかも確認します。

## 計算はコード、判断だけAI

コストを下げる一番効く方法は、AIに計算させないことです。

株の分析を例にします。
全部をAIに任せると、次の問題が出ます。

| 問題 | 内容 |
| --- | --- |
| 再現性がない | 同じデータでも、計算結果が毎回ぶれる |
| 量が増える | 銘柄数 × 毎日 で、使用量が膨らむ |
| 検証できない | 過去の判断を追いかけられない |

そこで、役割を分けます。

1. 移動平均や指標の計算は、Python などのコードで行う
2. コードが、上位の数件だけを決まった形に要約する
3. AIには、その要約だけを渡して「手法同士の矛盾をどう読むか」を判断させる

AIに渡す形は、次のように統一すると扱いやすくなります。

```json
{
  "code": "9432",
  "signal": "BUY",
  "score": 0.72,
  "confidence": 0.6,
  "summary": "25日線から-5.2%、直近に悪材料なし"
}
```

ある本では、この分け方でAIに渡す量が100分の1以下になったと報告されていました。
同じ考え方は、競馬の予想、ログの分析、テスト結果の集計にも使えます。

## 「決まった手順」は固定ワークフローに

手順が決まっている繰り返し作業は、AIに毎回計画させないほうが安く確実です。

| 作業の性質 | 向いている作り |
| --- | --- |
| 手順が決まっている（毎週の集計、定型の投稿） | 固定の手順書。AIは中身だけ作る |
| 手順を探す必要がある（原因不明のバグ調査） | AIに計画させる |

固定にすると、AIが手順を考える分の消費がなくなります。
そして、手順を飛ばす事故も減ります。

## よくある失敗

**頻度を上げてから費用に気づく**
1回分を測ってから掛け算します。

**APIキーをCIに設定したまま忘れる**
従量課金で動き続けます。
使っている認証方式を定期的に確かめます。

**全部をAIに計算させる**
費用が増え、結果もぶれます。
決まった計算はコードに任せます。

## この章のチェックリスト

- [ ] 1回分の消費を測ってから頻度を決めた
- [ ] 時間・回数・金額の3つに上限がある
- [ ] CI のタイムアウトを短く設定した
- [ ] 自分のプランで、非対話・CIの利用がどう数えられるか確かめた
- [ ] APIキーを使っている場所を把握している
- [ ] 決まった計算はコードで行い、AIには要約だけ渡している
